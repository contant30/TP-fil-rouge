Système de réservation : salles, ressources, créneaux horaires

Étape 2 — Analyse du cahier des charges

Cahier des charges 

Description générale : Application qui permet de reserver des salles de réunion et de cocher les ressources utilisées.
L'interface de reservation se ferat sur une page web sur laquel il y aura un calendrier du lundi au vendredi de 8h00 a 17h00.

Fonctionnalités :
- Gestion des salles de réunion
- Gestion des ressources
- Gestion des réservations
- Gestion des utilisateurs

Contraintes techniques : 
- Front end : HTML, CSS, JS
- Back end : Node.js + express
- Base de données : Mysql
- Authentification : JWT et mots de passe hashés

Ecrans obligatoires :
- Page de connexion
- Page d'inscription
- Page de gestion des salles
- Page de gestion des ressources
- Page de gestion des réservations
- Page de gestion des utilisateurs
- Page de bienvenue

Règles métier :
- Une reservation doit avoir le nom de la salle, le nom de l'utilisateur, la date, le créneau et les ressources.
- Un utilisateur peut faire plusieurs reservations.
- Une salle peut être reservée que par un utilisateur à la fois.
- Un créneau horaire peut être reservé que par un utilisateur à la fois.
- Une ressource peut etre reservée que par un utilisateur à la fois.
- Un utilisateur peut se connecter avec un nom d'utilisateur, un mot de passe et se deconnecter.
- Un utilisateur peut se modifier et se supprimer.
- Une reservation ne peut etre supprimée que par l'utilisateur qui l'a faite.

Contraintes métier :

-Un créneau donné (date + heure) ne peut être réservé qu’une fois pour une même salle.
-Seul l’utilisateur ayant créé la réservation peut la supprimer.
